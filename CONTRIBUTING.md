# Contributing to the Project

Thank you for your interest in contributing!

We welcome bug fixes, compatibility improvements, performance optimizations, translations, accessibility improvements, and other changes that benefit the project.

Please read these guidelines before submitting a contribution.

Contributing does not grant permission to publish an independent modified distribution.

## 2. How to Contribute

### Bug Reports

Before reporting a bug, please search existing issues to avoid duplicates.

When submitting a bug report, include:

- A clear description of the issue.
- Steps to reproduce it.
- The expected and actual behavior.
- Relevant platform and software version information.
- Logs or screenshots, where appropriate.

### Feature Requests

Please open an issue before implementing substantial new features or architectural changes.

The project aims to maintain a coherent and consistent product experience. Not every proposed feature will necessarily be accepted, even if it is technically feasible.

### Pull Requests

1. Fork the repository and create a development branch.
2. Make focused changes consistent with the project's architecture and conventions.
3. Include tests or documentation where appropriate.
4. Ensure existing functionality remains unaffected.
5. Open a Pull Request describing the motivation and implementation.

Please avoid combining unrelated changes in a single Pull Request.

The maintainers may request revisions, decline contributions, or choose alternative implementations.
